# 周辺視野テスト v1.8.7

GitHub Pagesに `index.html` を置いて公開できる、外部ライブラリ不要のHTML＋JavaScriptアプリです。

## 操作

1. 条件（基本・大・緑・赤・青）を選びます。
2. 画面をタッチして開始します。認識の開始と、対応しているブラウザではマイクの音声キャプチャ開始を確認してから図形を表示します。
3. 上・右・下・左・丸を発話してください（北・東・南・西、登録済みの誤変換候補も使用できます）。各図形は1.5秒ずつ、5種類を重複なしで表示します。
4. 5枚目の表示が終わった後も2秒間は回答を受け付け、認識サービスの終了イベントを待ってから結果を集計します。
5. CSVに結果と認識イベントログを保存できます。

## v1.8.7 の音声認識改善

- 前回の `SpeechRecognition` が終了した (`end` イベント) ことを確認してからインスタンスを破棄します。
- 正常終了後には `abort()` を呼ばず、`stop()` → `end` で完了します。
- マイクのセッション解放に最低1.8秒の間隔を設けます（通常ブラウザ）。
- iPhone/iPadでは「同じ条件でもう一度」から、条件を維持しつつページをリロードします。iOSの音声入力セッションを引き継がないための対処です。
- 開始要求、認識開始、`audiostart`、`audioend`、認識終了、エラーを診断ログへ追加しました。
- 停止が完了しない場合は強制終了後に警告し、再読み込み以外で再測定を開始しないようにします。
- 待機画面に「マイクの権限・接続を確認」を設置。押した場合だけ `getUserMedia` で許可を確認し、取得したトラックは直ちに停止します。音声認識と同時利用はしません。
- 音声認識結果が0件の場合は再読み込みを案内します。

### 注意

iOS Safari / WebKitには、1回目に成功しても2回目の `SpeechRecognition` が音声を受信しない不具合の報告があります。正常な終了処理やページ再読み込みを行っても、端末・OSによっては解消できない可能性があります。

「マイクの権限・接続を確認」は、OSによるマイク利用許可を確認するだけで、Web Speech APIの文字起こしが実際に成功する保証ではありません。権限ダイアログの再表示はブラウザが管理し、アプリから強制できません。

反応時間は、回答語が暫定・確定の認識テキストへ初めて現れた時刻から表示開始時刻を引いて記録します。音声認識の処理遅延を含みます。発話時刻の「推定」は参考値であり、音声波形の実測ではありません。

## 実装テスト

デスクトップChromiumの模擬SpeechRecognitionを用い、2回連続の正常開始・終了、`stop`後に`end`が届かない場合の再測定ブロック、マイク権限確認でストリームが必ず解放されることを確認しました。実際のiPhoneのマイクは未検証です。
